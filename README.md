# Вайб-кодинг для ИТ-интегратора

Практический учебник по AI-first разработке для сотрудников КОРУС Консалтинг с нулевым опытом программирования.

Учебник помогает пройти путь от идеи продукта до работающего web-приложения с прототипом, GitHub-репозиторием, базой данных, авторизацией, деплоем, AI-фичами и агентной разработкой.

## Для кого

Учебник предназначен для рядового сотрудника ИТ-интегратора:

- бизнес-аналитика;
- консультанта;
- пресейла;
- проектного менеджера;
- начинающего product owner;
- сотрудника, который хочет научиться создавать рабочие прототипы с помощью AI-инструментов.

Аудитория может не уметь программировать, но готова учиться и разбираться в коде, данных, API, GitHub, деплое и AI-инструментах.

## Главная цель

Научить сотрудника не просто генерировать приложения через AI, а управляемо проходить полный цикл AI-first разработки:

1. сформулировать идею продукта;
2. создать первый прототип;
3. сохранить код в GitHub;
4. подключить базу данных;
5. настроить авторизацию;
6. задеплоить приложение;
7. встроить AI-фичу;
8. использовать AI-агентов для аудита, тестов и рефакторинга;
9. подготовить финальное демо;
10. понимать ограничения, риски и зоны human review.

## Сквозной учебный проект

Основной проект учебника — **AI Advisory Intake Assistant**.

Это web-приложение для сотрудника ИТ-интегратора, которое помогает собрать первичную информацию по клиентскому запросу перед advisory, пресейлом или обследованием.

Приложение постепенно развивается по ходу учебника:

- идея и product brief;
- первый прототип;
- GitHub-репозиторий;
- база данных Supabase;
- авторизация;
- деплой на Vercel;
- AI-фича через Anthropic API;
- агентный аудит;
- финальное демо.

## Принципы учебника

1. Сначала объяснение простым языком, потом технический термин.
2. Каждая глава даёт практический результат.
3. Каждая глава создаёт артефакт: шаблон, чек-лист, карту, файл, промпт, схему или рабочий элемент приложения.
4. AI помогает ускорить работу, но не заменяет человека.
5. В каждой сложной теме есть human review.
6. Прототип не называется production-ready без проверки.
7. Реальные клиентские данные, секреты, токены и пароли не используются.
8. Сложные темы безопасности и качества выносятся в приложения.
